# گزارش واقعی پخش FarsiPlex — Pooyan TV

## نتیجهٔ اصلی
قسمت 1 میمون مست واقعاً داخل Media3 پخش شد. فایل نمونهٔ 1080p ارائه‌شده جداگانه آزمایش شد؛ نسخهٔ نهایی نیز منبع تازهٔ 720p را از مسیر عمومی پلیر سایت کشف و بدون لینک دستی پخش کرد. این نتیجه محدود به زمان و عناوین آزمایش‌شده است؛ معادل تضمین حقوق پخش، مجوز تجاری شخص ثالث یا پایداری دائمی سرویس نیست.

## 1. HTTP فایل نمونهٔ 1080p
با همان URL ارائه‌شده، بدون ارسال کوکی، Authorization یا Referer ویژه:
- HEAD: 200 OK؛ Content-Type: video/mp4؛ Content-Length: 1002089306؛ Accept-Ranges: bytes؛ redirect نداشت.
- GET با Range bytes=0-4095: 206 Partial Content؛ Content-Length: 4096؛ Content-Range: bytes 0-4095/1002089306. فقط 4096 بایت در این آزمون دریافت شد، نه کل فیلم.
- همان مسیر بدون پارامتر md5 نیز در همین زمان HEAD=200 و Range=206 داد. این صرفاً رفتار مشاهده‌شدهٔ سرور است؛ حذف یا تغییر امضا در resolver انجام نمی‌شود و پارامترهای واقعی سایت حفظ می‌شوند.
- انقضای URL در بازهٔ این آزمون مشاهده نشد. زمان انقضا و اعتبار آینده تعیین نشده‌اند؛ هیچ امضا ساخته، حدس، تمدید یا brute-force نشد. مقدار واقعی query در مخزن و گزارش عمومی درج نشده است.

## 2. معماری مشاهده‌شده
صفحهٔ رسمی episode/meymoone-mast-ep01 فرم عمومی watch با hidden id همان قسمت دارد. JavaScript با کلیک، همان فرم را به /play/ با POST ارسال می‌کند. پاسخ 302 به یکی از صفحات پخش خود سایت می‌رود؛ در چند درخواست نام مسیرهایی مانند play-online-video و play-vip-stream متفاوت بود. صفحهٔ پخش یک iframe از /jwplayer/ همان دامنه معرفی می‌کند. JSON عمومی var jw در آن صفحه، file را روی pl.farsiplex.buzz معرفی می‌کند. بنابراین ارتباط این میزبان با زیرساخت پخش رسمی سایت در این مشاهده تأیید شد.

بازکردن مستقیم play-exclusive-content بدون زمینهٔ قسمت، پیام no_post_id داشت؛ اسم صفحه به‌تنهایی برای resolve کافی نیست. شناسهٔ قسمت فقط از فرم واقعی خوانده می‌شود، نه با حدس. هیچ API خصوصی، ورود حساب، پرداخت، CAPTCHA، DRM یا محدودیت دسترسی دور زده نشد. کوکی‌های موقت حاصل از همان جریان عمومی، فقط در همان دامنه و همان resolve نگهداری می‌شوند و به CDN ارسال نمی‌شوند. هیچ کوکی مرورگر کاربر کپی نشده است.

شرایط عمومی سایت در https://farsiplex.com/terms/ بررسی شد؛ API رسمی مستند یا مجوز مشخص یکپارچه‌سازی تجاری برای Pooyan TV تأیید نشد. برای انتشار گسترده/تجاری باید مجوز و قرارداد/API رسمی FarsiPlex اخذ شود. عمومی‌بودن مسیر، تضمین مالکیت حقوق تمام آثار نیست. در پاسخ 401/402/403 برنامه از مانع عبور نمی‌کند.

## 3. اصلاح resolver و جست‌وجو
- مسیر داخلی فقط از فرم عمومی همان عنوان شروع می‌شود؛ endpoint عمومی /resolve همچنان movie/tvshow/episode می‌پذیرد و arbitrary URL نمی‌گیرد.
- redirectها فقط HTTPS، بدون userinfo/port اضافی و روی farsiplex.com با مسیرهای پلیر مجاز دنبال می‌شوند. iframe فقط /jwplayer/ همان دامنه است.
- JSON پلیر به‌صورت ساختاری با تشخیص رشته‌ها، escapeها و تودرتویی خوانده می‌شود؛ JavaScript اجرا یا eval نمی‌شود. ایراد parser اولیه در مواجهه با semicolon داخل رشتهٔ JSON در آزمون واقعی پیدا و رفع شد.
- میزبان دقیق pl.farsiplex.buzz به allowlist پیش‌فرض و wrangler.toml اضافه شد؛ wildcard اضافه نشد. media file2 روی میزبان دیگری عمداً انتخاب نمی‌شود.
- Android امضای بایت‌های MP4/WebM یا محتوای HLS/DASH را با GET محدود بررسی می‌کند. Worker علاوه بر منشأ واقعی لینک، وضعیت و نوع HTTP را بررسی می‌کند؛ موفقیت Worker به‌تنهایی شاهد پخش نیست.
- هر بار بازکردن جزئیات، مسیر رسمی دوباره دریافت می‌شود؛ URL امضاشده در سورس ثابت نشده است.
- جست‌وجو اکنون از جست‌وجوی عمومی خود سایت استفاده می‌کند؛ درخواست فارسی «میمون مست» در آزمون HTTP عنوان درست را برگرداند. روی TV ورودی لاتین Meymoone آزمایش شد؛ ورود فارسی با صفحه‌کلید نصب‌شدهٔ Sogou و ADB در این نوبت انجام نشد. بنابراین زنجیرهٔ دقیق تایپ فارسی با ریموت کاملاً آزمایش‌شده اعلام نمی‌شود.

## 4. Media3 روی تلویزیون
- نصب نهایی: Success؛ اجرای سرد: Status ok، 929ms.
- مسیر سریال → قسمت 1 → دریافت جزئیات → نمایش خودکار دکمهٔ پخش → Media3 انجام شد. لینک دستی در نسخهٔ نهایی وارد نشد و Worker/DeepSeek برای این مسیر لازم نبود.
- نمونهٔ 1080p کاربر: تصویر واقعی و رمزگشای سخت‌افزاری c2.mtk.avc.decoder، 1920×1080 حدود 24fps ثبت شد.
- منبع تازهٔ سایت در نسخهٔ نهایی: 1280×720 حدود 24fps؛ چندین بازهٔ سه‌ثانیه‌ای با حدود 72 فریم رندر و Drop=0 مشاهده شد. تصویر واقعی ثبت شد.
- AAC راه‌اندازی شد. AudioFlinger یک track فعال مخصوص PID همین برنامه با خروجی PCM استریو 48000Hz، gain صفر dB و output خارج از standby نشان داد. این تأیید مسیر خروجی صوتی Android است؛ صدای فیزیکی بلندگو توسط اپراتور انسانی شنیده/تأیید نشده است.
- Pause دکمه را به «پخش» و Resume به «مکث» تغییر داد. Seek جلو 30s و عقب 10s اجرا شد؛ تصویر مقصد و نمایش زمان 1:18 ثبت شد. موقعیت 71505ms از مدت 3077462ms روی دستگاه ذخیره شد. نمونهٔ 1080p نیز موقعیت 83799ms ذخیره کرد.
- Player بسته و دوباره باز شد؛ همچنین به سریال برگشتیم، قسمت مجدداً باز و resolve تازه انجام شد؛ دوباره دکمهٔ پخش و رندر پیوسته مشاهده شد.
- در بازهٔ چنددقیقه‌ای آزمون، ExoPlayerImplInternal خطای پخش و AndroidRuntime Fatal برای PID نسخهٔ نهایی نشان ندادند. کل قسمت حدود 51 دقیقه است و کامل تماشا نشده؛ آزمون بلندمدت انجام نشده است.
- در پایان پخش pause شد تا استریم بی‌دلیل ادامه پیدا نکند.

## 5. آزمون‌ها و محدودیت انتشار
JDK17، SDK35، Gradle8.9، assembleDebug، testDebugUnitTest و lintDebug در CI موفق‌اند. 55 بررسی مستقل Java و 9 تست Worker موفق‌اند. بررسی نمادها و سینتکس 20 فایل Java موفق بود. یک اجرای میانی به‌علت Maven HTTP429 شکست خورد؛ retry محدود اضافه شد و اجرای نهایی موفق بود.

سورس Worker جدید به‌صورت محلی با درخواست واقعی همین episode و یک فیلم دیگر Tars Az Ashk Haye Vaghei اجرا شد؛ هر دو status=playable، verified=true، searchUsed=false دادند. فیلم دوم داخل Media3 آزمایش نشده و پشتیبانی همهٔ عناوین ادعا نمی‌شود. HLS/DASH در کد پشتیبانی می‌شوند ولی در این نوبت با محتوای واقعی تست نشدند.

دسترسی مجاز انتشار Cloudflare وجود نداشت؛ Worker زندهٔ حساب کاربر به این سورس جدید ارتقا داده نشده است. تغییرات Worker در شاخه آماده و آزموده‌اند؛ resolver بومی Android مسیر پخش را مستقل انجام می‌دهد. کلید DeepSeek و access token در APK، GitHub و این گزارش قرار نگرفته‌اند. APK هنوز Debug است و کلید امضای ثابت برای ارتقاهای آینده باید تنظیم شود.
